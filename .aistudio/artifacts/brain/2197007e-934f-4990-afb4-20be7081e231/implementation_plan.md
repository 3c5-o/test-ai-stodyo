# خطة تحسين مبايلي برو وتوليد APK عبر GitHub Actions

خطة شاملة لترقية وتطوير تطبيق **مبايلي برو (Mobily Pro)** لإدارة محلات وصيانة الهواتف، وإعداد نظام أتمتة مستودع GitHub (CI/CD) لبناء وتصدير ملف الـ **APK** تلقائياً ونشره في قسم الـ Releases عند كل دفع (Push)، مع تحسين الخطوط العربية وتصدير الفواتير والنسخ الاحتياطي السحابي/المحلي.

---

## مراجعة المستخدم والقرارات الحاسمة (User Review & Critical Decisions)

> [!IMPORTANT]
> تم تأكيد الخيارات الرئيسية التالية وفق إجاباتك:
> 1. **بناء APK ونشره تلقائياً**: إعداد ملف سير عمل GitHub Actions يبني حزمة `assembleDebug` ويرفع ملف الـ APK كـ Artifact ويصدر Release تلقائي مع كل Push.
> 2. **أولويات التحسين المختارة**:
>    - تحسينات بصرية مع خط عربي احترافي عالي الدقة (Cairo / Tajawal).
>    - مشاركة وتصدير فواتير المبيعات وسندات الصيانة بجودة عالية ومناسبة للطباعة والمشاركة عبر واتساب.
>    - نسخ احتياطي للبيانات واستعادتها بملف JSON محلي، مع فلاتر وبحث فوري في المخزون والصيانة.

---

## 1. نظرة عامة والمفهوم الأساسي (Overview & Core Concept)

- **الهدف الأساسي**: تمكين المستخدم من إدارة متجره بالكامل دون عوائق تقنية، والحصول على ملف APK جاهز للتثبيت على الهاتف بمجرد رفع الكود إلى GitHub، دون الحاجة للتعامل مع بيئات سطر الأوامر أو أخطاء بناء Java القديمة في الهواتف.
- **الفئة المستهدفة**: أصحاب محلات الهواتف، فنيو الصيانة، وموظفو المبيعات ونقاط البيع (POS).
- **القيمة المضافة**:
  - تحميل التطبيق بضغطة زر من صفحة Releases في GitHub.
  - تجربة عربية سلسة متكاملة الخطوط والتنسيقات.
  - أمان وحفظ للبيانات من خلال ميزة النسخ الاحتياطي والاستعادة.
  - فواتير وسندات استلام احترافية تدعم المشاركة الفورية مع الزبائن.

---

## 2. تجربة المستخدم والتصميم البصري (User Experience & Visual Design)

### تدفقات المستخدم الرئيسية (User Flows):
1. **مسار تنزيل وتحديث التطبيق عبر GitHub Actions**:
   - يقوم المطور برفع الكود إلى GitHub (`git push`).
   - يقوم GitHub Actions تلقائياً بتهيئة Java 17 و Android SDK وبناء الـ APK.
   - يتوفر الـ APK فوراً في قسم **Releases** برابط تحميل مباشر للجوال.
2. **مسار إصدار ومشاركة الفاتورة**:
   - عند إتمام عملية بيع في نقطة البيع (POS) أو تسليم جهاز صيانة، يظهر زر "مشاركة الفاتورة / طباعة".
   - إمكانية مشاركة نص الفاتورة المنظم مع رابط ورسالة جاهزة للواتساب، أو حفظ نسخة رقمية.
3. **مسار النسخ الاحتياطي السريع**:
   - من شاشة الإعدادات، يضغط المستخدم على "تصدير نسخة احتياطية" لحفظ قاعدة البيانات كملف JSON آمن في التنزيلات.
   - إمكانية استعادة البيانات في أي وقت أو نقلها لهاتف آخر.
4. **مسار البحث والتصفية المتقدمة**:
   - شريط بحث ديناميكي فوري في شاشات المخزون والصيانة والأقساط، مع شرائح تصفية سريعة (ماركة الجهاز، حالة الصيانة: قيد الفحص / جاهز / تم التسليم، الأجهزة منخفضة الكمية).

### الهوية البصرية والخطوط:
- **الخطوط**: تثبيت وتضمين خط **Cairo** العربي المتناسق داخل موارد التطبيق محلياً لتوفير قراءة واضحة للأرقام والحروف والأسعار.
- **لوحة الألوان**: تباين عالي من نمط Material 3 مع دعم الوضعين الداكن والفاتح، واستخدام درجات أزرق زمردي وتقني وأخضر للعمليات الناجحة وأحمر للتنبيهات.
- **العناصر التفاعلية**: بطاقات ذات زوايا ناعمة وتأثيرات تموج (Ripples) عند النقر، وشارات ملونة لحالات الأجهزة والفواتير.

## 3. القرارات التقنية والمفاضلات (Key Product Decisions)

- **نظام GitHub Actions**:
  - *الخيار المعتمد*: إنشاء ملف `.github/workflows/build-apk.yml` مجهز بأحدث أدوات Gradle و JDK 17 وتخزين مؤقت (Gradle Caching) لتسريع البناء إلى أقل من 3 دقائق.
  - *السبب*: حل نهائي ودائم لمشكلة بيئة الهاتف المحدودة في AndroidIDE التي كانت تفتقر لـ Java 17 وتواجه مشاكل في الأقواس والمسافات.
- **تصدير الفواتير**:
  - *الخيار المعتمد*: توفير آلية مشاركة متعددة الأنماط: نص منسق مخصص لرسائل الواتساب مع خيارات النسخ والحفظ، وعرض بطاقة الفاتورة بتصميم Thermal Receipt متوافق مع الطابعات المحمولة.
  - *السبب*: تلبية متطلبات المتاجر في التواصل السريع مع العملاء دون تعقيد إعدادات الطابعات.
- **تخزين البيانات والنسخ الاحتياطي**:
  - *الخيار المعتمد*: إدارة التصدير والاستيراد لملفات النسخ الاحتياطي عبر Gson / Kotlin Serialization بصيغة JSON قابلة للقراءة والنقل مع حماية من الأخطاء أثناء الاستعادة.
  - *السبب*: العمل بدون إنترنت بنسبة 100% مع ضمان عدم ضياع أي بيانات تجارية.

## خطة التنفيذ المباشرة (Execution Steps):

1. **إعداد GitHub Actions**:
   - إنشاء مجلد وملف سير العمل `.github/workflows/build-apk.yml`.
   - ضبط خطوات البناء الآلي لإنتاج `app-debug.apk` وحفظه في Artifacts ونشره تلقائياً في Releases.
   - كتابة دليل تعليمات سريع وواضح باللغة العربية يشرح كيفية ربط المستودع وتنزيل الـ APK مباشرة.

2. **تحسين الخطوط العربية والمظهر (Typography & UI)**:
   - تنزيل خط **Cairo** وتثبيته في `app/src/main/res/font/`.
   - تحديث `Theme.kt` و `Typography` لربط خط Cairo بكافة عناصر التطبيق.
   - تحسين تناسق الشاشات ودعم كامل لاتجاه النصوص RTL.

3. **تطوير ميزة الفواتير والسندات (Invoices & Sharing)**:
   - تحسين نافذة تفاصيل الفاتورة `InvoiceDetailDialog.kt`.
   - إضافة زر "مشاركة عبر واتساب" مع نص منظم يحتوي على تفاصيل المشتريات والمحل والضمان.
   - دعم حفظ سند الصيانة وفاتورة المبيعات لمشاركتها بسهولة.

4. **تطوير النسخ الاحتياطي والبحث المتقدم (Backup & Search)**:
   - إضافة إمكانية تصدير واستيراد النسخ الاحتياطية بصيغة JSON داخل `SettingsScreen.kt`.
   - ترقية حقول البحث في `InventoryScreen` و `RepairsScreen` بفلاتر تصفية ذكية حسب الحالة والماركة والتاريخ.

5. **فحص وبناء المشروع وتأكيد استقراره**:
   - التحقق من تجميع الكود عبر `compile_applet` وضمان خلوه من أي أخطاء.
