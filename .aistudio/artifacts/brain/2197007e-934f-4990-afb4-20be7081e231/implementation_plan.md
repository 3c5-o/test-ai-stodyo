# خطة حل مشكلة حزمة التطبيق وإضافة التوقيع الحقيقي والأيقونة الرسمية

خطة شاملة لمعالجة خطأ "حزمة التطبيق غير صالحة" (Parse Error)، وتوليد مفتاح توقيع رسمي دائم (Release Keystore)، وتصميم أيقونة تطبيق احترافية وعصرية لمتجر **مبايلي برو (Mobily Pro)**، وتجهيز نسختي تثبيت (Release APK و Debug APK) مع روابط تنزيل مباشرة.

---

## مراجعة المستخدم والقرارات المؤكدة

> [!IMPORTANT]
> تم تأكيد خيار التوقيع والبناء: **توقيع حقيقي جاهز مع نسختين Release و Debug وتنزيل مباشر**. سيتم توفير مفتاح توقيع رسمي قياسي (RSA 2048) مع توقيع v1 + v2 + v3، وإعداد سير عمل GitHub لبناء ملفي `app-release.apk` و `app-debug.apk` ونشرهما فوراً.

- **القرار المؤكد 1**: توفير مفتاح توقيع إطلاق رسمي (`my-upload-key.jks`) مدمج، مع إمكانية التثبيت الفوري كنسخة إنتاج رسمية دون أخطاء شهادات التوقيع.
- **القرار المؤكد 2**: تصميم أيقونة تطبيق عصرية وفاخرة (شارة هاتف ذكي مع أدوات تقنية باللونين الكحلي والذهبي) متوافقة مع معايير Adaptive Icons لنظام أندرويد عبر كافة الدقات (`mdpi`, `hdpi`, `xhdpi`, `xxhdpi`, `xxxhdpi`).
- **القرار المؤكد 3**: معالجة أسباب خطأ "خطأ في حزمة التطبيق" عبر ضبط التوقيع الرقمي، والتحقق من سلامة الحزمة والملفات.

```
│                                │ يقلل موثوقية الحزمة لدى النظام.       │

```

## 3. خطوات التنفيذ التفصيلية

### أ. إنشاء مفتاح التوقيع الرسمي (Release Keystore)
1. إنشاء ملف Keystore رسمي دائم `my-upload-key.jks` متوافق مع معايير Android KeyStore (خوارزمية RSA 2048 بت وصلاحية 25 سنة وتوقيع v1 و v2 و v3).
2. ربط مفتاح التوقيع تلقائياً في `signingConfigs.release` داخل `app/build.gradle.kts`.
3. التأكد من قدرة المشروع على بناء `assembleRelease` محلياً وفي GitHub Actions بدون الحاجة لمدخلات يدوية.

### ب. تصميم وتوليد أيقونة التطبيق التكيفية (Adaptive App Icon)
1. توليد أيقونة هاتف ذكي فخمة بأدوات الصيانة والمبيعات عبر أداة توليد الصور المتوافقة مع معايير Material You.
2. إنشاء طبقة المقدمة `ic_launcher_foreground.xml` داخل منطقة الأمان القياسية (66dp).
3. إنشاء طبقة الخلفية `ic_launcher_background.xml` بلون كحلي ملكي متناسق.
4. توليد أيقونات الميب ماب النقطية (`ic_launcher.png` و `ic_launcher_round.png`) عبر جميع الكثافات الخمس (`mdpi`, `hdpi`, `xhdpi`, `xxhdpi`, `xxxhdpi`).
5. حذف أيقونات الويب الافتراضية القديمة لتجنب تضارب موارد الحزمة في أندرويد.

### ج. تحديث سير عمل GitHub Actions لإنتاج نسختي Release و Debug
1. تعديل `.github/workflows/build-apk.yml` لتشغيل أمرين معاً:
   - `./gradlew assembleRelease`: لإنتاج ملف `app-release.apk` الرسمي الموقع بالمفتاح المعتمد.
   - `./gradlew assembleDebug`: لإنتاج ملف `app-debug.apk`.
2. رفع الملفين معاً في المرفقات وإرفاقهما في صفحة الإصدارات (Releases) بروابط تحميل وتثبيت مباشرة.

### د. دليل التثبيت السليم على الهاتف لتفادي Parse Error
1. تضمين إرشادات تنزيل الملف المباشر (Raw Download) لمنع تنزيل صفحة الويب بالغلط على الهاتف.
2. تفعيل خيار تثبيت التطبيقات غير المعروفة لحزمة التطبيق.

## 4. التحقق والاختبار
- اختبار بناء النسخة الموقعة `./gradlew assembleRelease` والتأكد من نجاحها وإنتاج ملف الـ APK.
- اختبار `./gradlew assembleDebug` لضمان استقرار النسختين.
- فحص حجم وبنية الحزمة وتأكيد سلامة التوقيع الرقمي عبر أداة `compile_applet`.
